<article><H2 dir="auto">Compatibility Between ESP-IDF Releases and Revisions of Espressif SoCs</H2> <ul dir="auto"> <li><a href="https://github.com/espressif/esp-idf/blob/master/COMPATIBILITY_CN.md">中文版</a></li> </ul> <p dir="auto">This document describes the ESP-IDF support and compatibility for Espressif SoC series and revisions. The compatibility documents on release branches may be out-of-date. Please check the <a href="https://github.com/espressif/esp-idf/blob/master/COMPATIBILITY.md">Compatibility file on master</a> or ESP-IDF Release Notes for the latest chip support updates.</p> <H2 dir="auto">SoC Series Support</H2> <p dir="auto">Before official support, each SoC series typically provides <code>preview</code> versions on specific branches or tags for early development. Please note that preview support for these chips will end after the official release version is published, and will not be maintained afterwards. For mass production, please use the officially released versions.</p> <p dir="auto">After the first chip of a series completes support and passes testing, ESP-IDF will release the first official support version for that series. Chips of this series must run on this official version or higher.</p> <H2 dir="auto">Chip Revision Support</H2> <p dir="auto">After a chip series is officially supported, Espressif continues to release new chip revisions to improve performance. However, some performance improvements in new chip revisions depend on special software support, and sometimes new chip revisions must run under specific software versions to function normally.</p> <p dir="auto">See <a href="https://www.espressif.com/sites/default/files/advisory_downloads/AR2022-005%20Compatibility%20Advisory%20for%20Chip%20Revision%20Numbering%20%20Scheme.pdf">Compatibility Advisory for Chip Revision Numbering Scheme</a> on the versioning of Espressif SoC revisions.</p> <p dir="auto">You can run <code>esptool chip-id</code> to detect the chip series and revision (use <code>esptool.py chip_id</code> for ESP-IDF v5.5 and older). See <a href="https://www.espressif.com/en/support/documents/technical-documents?keys=errata">SoC Errata</a> for more on distinguishing chip revisions and revision improvements. Run <code>idf.py --version</code> to check the current ESP-IDF version.</p> <p dir="auto">There are <code>Recommended</code> and <code>Required</code> versions of ESP-IDF for each chip revision:</p> <ul dir="auto"> <li> <p dir="auto"><code>Recommended</code>: indicates the earliest ESP-IDF release version that currently gives the most complete support for utilizing all performance improvements of the chip revision. Using this version, software can maximize the benefits of the chip revision improvements. Running binary compiled with ESP-IDF below the <code>Recommended</code> version of a chip revision, software may not benefit from some of the bugfix/features provided by the chip revision. The chip will have almost the same behavior as its previous revision. If a chip revision involves many software updates, they may be released across multiple versions, so the recommended version may be updated periodically.</p> </li> <li> <p dir="auto"><code>Required</code>: indicates the minimum ESP-IDF version required for the chip revision to run normally. Running binary compiled below the <code>Required</code> version, the binary may have unpredictable behavior.</p> </li> </ul> <p dir="auto">Though the software can make use of all the features of a chip revision, if its version is higher than the <code>Recommended</code> version of the chip, it is still recommended to use the latest bugfix version of the release branch. The latest bugfix version fixes a number of issues and helps improve product stability.</p> <p dir="auto">For example, if we have a chip, whose <code>Required</code> / <code>Recommended</code> version of <code>release/v5.1</code> branch is <code>v5.1.2</code> / <code>v5.1.4</code>, and the latest release on that branch is <code>v5.1.6</code>. Then the chip will not boot up with ESP-IDF <code>v5.1</code> - <code>v5.1.1</code> or will have unpredictable behavior, and application may not make use of all benefits of the chip, when running with ESP-IDF <code>v5.1.2</code> or <code>v5.1.3</code>. Though <code>v5.1.4</code> will supports the chip revision, it is still recommended to upgrade ESP-IDF to <code>v5.1.6</code>.</p> <H2 dir="auto">Detailed ESP-IDF Support for Chip Revisions</H2> <H3 dir="auto">ESP32</H3> <H4 dir="auto">v0.0, v1.0, v3.0</H4> <p dir="auto">Supported since initial version of ESP-IDF.</p> <H4 dir="auto">v1.1</H4> <p dir="auto">To be added.</p> <H4 dir="auto">v2.0</H4> <p dir="auto">To be added.</p> <H4 dir="auto">v3.1</H4> <p dir="auto">To be added.</p> <H3 dir="auto">ESP32-S2</H3> <H4 dir="auto">v0.0</H4> <p dir="auto">Supported since ESP-IDF v4.2.</p> <H4 dir="auto">v1.0</H4> <markdown-accessiblity-table><table> <thead> <tr> <th>Release branch</th> <th>Recommended</th> <th>Required</th> </tr> </thead> <tbody> <tr> <td>release/v4.2</td> <td>v4.2.3+</td> <td>v4.2</td> </tr> <tr> <td>release/v4.3</td> <td>v4.3.3+</td> <td>v4.3</td> </tr> <tr> <td>release/v4.4</td> <td>v4.4.6+</td> <td>v4.4</td> </tr> <tr> <td>release/v5.0</td> <td>v5.0.4+</td> <td>v5.0</td> </tr> <tr> <td>release/v5.1</td> <td>v5.1.2+</td> <td>v5.1</td> </tr> <tr> <td>release/v5.2 and above</td> <td>v5.2+</td> <td>v5.2</td> </tr> </tbody> </table></markdown-accessiblity-table> <H3 dir="auto">ESP32-C3</H3> <H4 dir="auto">v0.2 - Lower than the Required Version?</H2> <p dir="auto">Latest ESP-IDF versions can prevent from downloading to, or even execute binaries on unsupported chips. ESP-IDF of versions v4.4.5+, v5.0.1+, v5.1 and above have both esptool download check and bootloader loading check against the chip revision. While ESP-IDF v4.3.5 has only esptool downloading check.</p> <p dir="auto">For earlier ESP-IDF versions without such checking, which is incompatible with the given chip revision, the chips running such versions will have unpredictable behavior.</p> </article>
